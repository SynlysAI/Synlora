# 学术研究流水线（Pipeline）

> **Synlora 沙箱适配（优先级高于本技能正文中的任何工具指导）**
>
> - 本技能是**编排器**：只做阶段识别、模式推荐、技能调度、交接与进度管理，自己不做研究/写作/评审的实质工作——实质工作按各阶段调度 `ars-deep-research` / `ars-academic-paper` / `ars-academic-paper-reviewer`（skill.read 读取后按其流程执行）。
> - 检索用 `web.search` / `web.fetch`；产物写 `output/` 并 file.send 交付；确认点用 `ask_user`。
> - 语言跟随用户，术语保留英文。

把三个技能编排成一条无缝流水线，外加两道诚信闸门与双向评审。**可选编排**：用户只需要单一功能（只查文献、只评审）时不启动流水线，直接路由到对应技能。

## 十阶段状态机

| 阶段 | 名称 | 调度 | 产出 |
|---|---|---|---|
| 1 | 研究 | `ars-deep-research`（socratic/full/quick） | 研究问题简报、方法蓝图、书目、综合 |
| 2 | 写作 | `ars-academic-paper`（plan/full） | 论文初稿 |
| 2.5 | **诚信检查** | 本技能诚信流程（pre-review） | 诚信报告 + 修正稿 |
| 3 | 评审 | `ars-academic-paper-reviewer`（full） | 5 席报告 + 编辑决定 + 修订路线图 |
| 4 | 修订 | `ars-academic-paper`（revision） | 修订稿 + 审稿回应 |
| 3' | 复核评审 | `ars-academic-paper-reviewer`（re-review） | 逐条核对 + 残余问题 |
| 4' | 再修订 | `ars-academic-paper`（revision，仅一轮） | 二修稿（如需） |
| 4.5 | **终检** | 本技能诚信流程（final-check） | 终检报告 |
| 5 | 定稿 | `ars-academic-paper`（format-convert） | 终稿（Markdown/Word；LaTeX 出源码） |
| 6 | 过程纪要 | 本技能 | 人机协作过程记录（可选，用户可跳过） |

## 入口检测（第一步必做）

分析用户手上有什么材料，判定入口并 `ask_user` 确认：

| 材料状态 | 入口 |
|---|---|
| 什么都没有 | 阶段 1 |
| 有研究数据/材料 | 阶段 2 |
| 有论文稿 | **阶段 2.5（不可跳过**，除非用户出示未超期的诚信报告且稿未改动） |
| 有已核验的稿 | 阶段 3 |
| 有审稿意见 | 阶段 4 |
| 有修订稿 | 阶段 3' |
| 只差格式化 | 阶段 5 |

## 模式推荐（入口确认后）

- 新手/要引导 → 阶段 1 socratic + 阶段 2 plan + 阶段 3 guided
- 老手/要直接产出 → 全 full
- 时间紧 → 阶段 1 quick + 阶段 2 full + 阶段 3 quick

推荐时解释模式差异让用户选，不替用户定。

## 检查点制度（铁律）

**每个阶段完成后必须主动提示并等待用户确认**，不许自动进入下一阶段。三档：

- **FULL**：首个检查点、诚信闸门后、定稿交付时——完整交付物清单 + 指标（字数/参考文献数/完成度）+ 标记问题 + 选项
- **SLIM**：用户连说 2 次"继续"后——一行状态 + 继续/暂停
- **MANDATORY**：诚信 FAIL、评审决定、定稿前——**不可跳过**，必须显式用户输入；用户可暂停退出，但不可跳过诚信检查

自检五问（每个 FULL 检查点前自问，有虑则呈报）：有未核实的引用吗？上一阶段有没有无批判地全盘接受反馈？各适用标准是改善/持平/退步/不可比？有没有加用户没要的内容？该阶段交付物齐了吗？

**防退化规则**：阶段 N 的产出质量 < 阶段 N−1 → 暂停，向用户说明，不得带病推进。

## 诚信闸门（阶段 2.5 与 4.5）

五相检查 + 七类 AI 失效模式清单，完整流程见 `references/integrity-checks.md`。要点：

- 阶段 2.5（稿前）：文献 100% 核真 + 引文语境抽查 ≥30% + 统计面全覆盖 + 原创性抽查 + 高影响主张全量核验
- 阶段 4.5（定稿前）：**全部**范围提至 100%（文献/引文语境/统计面/主张），且必须**从头重查**——只复查 2.5 已知问题是反模式，修订可能引入新问题
- FAIL → 修正后复查，最多 3 轮；3 轮后仍有未决项 → 列明并 `ask_user` 让用户显式决定（记录理由），**永不静默丢弃未决项**
- 任何失效模式 SUSPECTED → 阻断，用户确认/有据推翻/修订三选一后才放行

## 双向评审环

阶段 3 评审 → 阶段 4 修订 → 阶段 3' 复核 →（Major 时）阶段 4' 再修订 → 直接进 4.5 **不再回评审**。硬上限：修订环最多 1 轮完整循环（阶段 4 + 4' 各一次），替代单技能的 2 轮规则；遗留问题标为「已确认局限」。每轮结束给累计修订史（各轮决定、已处理项、未决项）。

**早停判据**（四条全满足才建议停）：无 P0 问题残留 / 无未决的决定性退步 / 无适用标准发生需要再修的实质变化 / 作者无待办动作。用户可否决。

## 交接协议

- 1→2：研究问题简报 + 方法蓝图 + 注释书目 + 综合报告（写作技能的 intake 自动识别并跳过冗余步骤）
- 2→2.5→3：完整论文 → 诚信报告 → 评审（带诚信结论）
- 3→4：修订路线图 + 编辑决定信
- 4→3'：修订稿 + 审稿回应 + 原路线图
- 3'→4.5 或 4/4'→4.5：修订完成稿 + 逐条核对残留记录
- 4.5→5：终检 PASS 稿 + 引用风格决定（用户在定稿闸门确认）
- 5→6：交付物清单（用户可拒绝阶段 6，标记 skipped 正常完结）

## 阶段 6：过程纪要（可选）

产出"论文创作过程记录"：各阶段决策轨迹、修订轮历史、诚信检查结论、失效模式审计日志（各模式最终状态与被推翻时的用户理由）、AI 自省报告（哪些地方 AI 可能带偏了方向、用户哪些把关起了作用）。用户明确确认接受交付物后流水线置为 completed。

## 反模式

| # | 反模式 | 正确行为 |
|---|---|---|
| 1 | "看着挺好，跳过诚信检查" | 2.5/4.5 不可自动跳过 |
| 2 | 编排器亲自写内容 | 只调度，实质工作归技能 |
| 3 | 自动闯过 MANDATORY 检查点 | 必须显式用户输入 |
| 4 | 阶段质量退化还硬推 | 暂停并说明 |
| 5 | 静默丢弃审稿意见 | 逐条有去向（已处理/未处理/不采纳+理由） |
| 6 | 终检只复查旧问题 | 从头全量重查 |
| 7 | 过程评分自嗨 | 诚实第一，每分有据 |

## 失败恢复

| 阶段 | 故障 | 处置 |
|---|---|---|
| 入口 | 判定不了入口 | 直接问用户有什么、要什么 |
| 1 | 研究不收敛 | 建议 socratic→full 或收窄范围 |
| 2 | 研究基础不足 | 建议回阶段 1 补研究 |
| 2.5 | 3 轮仍 FAIL | 列不可核实项，用户显式决定 |
| 3 | 评审 Reject | 给选项：大重构（回阶段 2）或放弃 |
| 4 | 修订不全 | 列未处理项问是否继续 |
| 3' | 复核仍有重大问题 | 进 4' 终轮修订 |
| 4.5 | 终检 FAIL | 修→复查（≤3 轮） |
| 任意 | 用户离开 | 保存状态与产出，给重入口描述 |
| 任意 | 技能执行失败 | 报错 + 重试/暂停/换模式三选项；不跳过任何强制闸门 |
